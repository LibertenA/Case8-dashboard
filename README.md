# Веб-дашборд мониторинга показателей

## Инструкция запуска
Требуется Node.js 18+. Зависимости npm не нужны. Библиотеки подгружаются с CDN (cdnjs.cloudflare.com, резерв — cdn.jsdelivr.net); для работы без интернета положите `react.production.min.js`, `react-dom.production.min.js` и `chart.umd.js` в `public/vendor`.

```
npm start
```

Открыть http://localhost:3000. Порт задаётся переменной окружения `PORT`.

## Источник тестовых данных
Данные **генерируются алгоритмически** при старте сервера и далее в реальном времени. Внешние датасеты, парсинг и нейросетевая генерация **не используются**.

- Нагрузка объекта (%) = базовый уровень + суточная синусоида со смещением фазы + случайный шум, ограничение 3–100.
- При старте создаётся суточная история с шагом 1 минута и 40 инцидентов; далее каждые 3 секунды — новое измерение по каждому объекту.
- Новый инцидент с вероятностью 5% на шаг; уровни: критический 15%, серьёзный 35%, незначительный 50%; длительность 2–25 минут, затем статус «Устранён».

**Обоснование:** суточный профиль, пороги (70% и 85%), распределение уровней и время устранения воспроизводят типовую картину диспетчерской инженерных сетей и достаточны для проверки фильтров, обновления данных и сценария потери связи.

**Этическая и юридическая оговорка:** данные синтетические, реальных персональных данных третьих лиц не содержат; сгенерированные изображения людей не используются.

## Архитектура обмена данными
Сервер (`server.js`, встроенный модуль `http`) и клиент (React, `public/app.js`) обмениваются по REST и SSE.

| Маршрут | Назначение |
|---|---|
| `GET /api/meta` | Справочник категорий и объектов, пороги нагрузки |
| `GET /api/history?since=<мс>` | Измерения и инциденты после метки времени (без параметра — суточная история) |
| `GET /api/stream` | SSE-поток, событие `tick` раз в 3 секунды: новые измерения и новые/обновлённые инциденты |

Порядок работы клиента:
1. Открывает SSE; после `onopen` запрашивает `/api/meta` и `/api/history?since=<метка>`.
2. События `tick` добавляются в локальное состояние без перезагрузки страницы.
3. Фильтры применяются к локальному состоянию — все виджеты меняются синхронно.
4. При ошибке потока или отсутствии сообщений >10 секунд — баннер потери связи; повторные попытки с задержкой 2, 4, 8, 10 секунд.
5. После переподключения докачивает пропущенные данные через `/api/history?since=...` и показывает баннер «Соединение восстановлено» на 4 секунды.

Сервер хранит данные за 24 часа в памяти; статика отдаётся только из `public`; разрешены GET и HEAD; заданы `Content-Security-Policy` и `X-Content-Type-Options`.
